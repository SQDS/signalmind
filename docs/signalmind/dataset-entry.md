# 整库入口使用说明

工作台的“整库分组清洗”和命令行的 `tsmcp-clean dataset` 调用同一调度器。运行规范描述数据来源、用途、TaskPack、病例清单或抽样种子、探查灵敏度、分组方式和预算。Vital 使用上游 inventory。CSV/NPZ 使用已有工作台通道和时间映射。Vital 的个体阈值按患者重新计算，CSV/NPZ 按原始文件记录处理，跨文件不拼接。

## 启动与续跑

从项目根目录运行本地规则对照：

```bash
.venv/bin/tsmcp-clean dataset \
  --spec configs/cleaning/dataset-entry.example.json \
  --workspace eval/runs/my-dataset-rules
```

复制示例规范后，将 `config.method` 设为 `dataset_agent` 并指定 `api_cap` 即可实际运行 DeepSeek。工作区取一个新目录，命令追加 `--live`。已有共享预算时，把 `config.budget_root` 指向该账本目录，`api_cap` 填其累计上限。DS 返回用量、未确认费用预留和单次运行的增量分别记账。配置中的数据、清单、账本和回执路径都相对规范文件解析。

- `patient_manifest` 接受患者键列表或带 `patients` 列表的 JSON。未指定时用 `patients` 和 `seed` 从既有训练分区抽样。主动重放已经选过的病例时，在指定同一清单的同时设置 `reuse_development: true`。
- `tasks` 决定启用哪几路，`purpose` 保存用途并传给修补角色。`inspection_preset` 可选 `quick`、`balanced`、`thorough`。`secondary_probe: true` 额外比较两种本通道检测。ECG 比较使用项目评测环境里安装的 WFDB。
- `routing: reason` 按通道及原始触发原因归组。选择 `jev` 时设置 `jev_token_cap` 并在进程环境提供 `WULUSAI_API_KEY`。JEV 每条提示只接收其数值特征，回执按内容缓存，用量以 token 单列。该独立配额与 DS 美元账本分开。JEV 配额不足的提示单列为未分流，运行标记部分完成。
- `joint_views` 在这一版限制每个记录的跨通道图片数。持续事件按 10 秒分片，优先给不同事件安排焦点图，再分配剩余分片。可靠的同采集块和时间范围用于联合取证。每路另外采样一处未报警对照（有合适范围时）。若两个通道同时报警且其中一处按组判读后仍待核，才进入额外联合取证队列。未选中同步图时保留逐拍原判，并单列 joint_view_unchecked。实际拟写入却未获审核的位置仍保持原波形，并记录原因。
- `write_views` 限制每个记录审批波形写入的图片数，粗修和精修共享。候选块的所有写入范围均获放行才发布该块。预算或证据不足时回到父版本并记录待核。30 秒图册由 `atlas` 控制。
- 每组单独发送一条结构化请求，含两张图和该组全部成员的数值表。多成员组取典型与边界成员，单成员组取同一处的上下文及局部放大。对于孤立窄尖峰，两张代表图各自并排显示搏动上下文和带原始采样点的细节，并随表发送每个核心的原始采样值。每行保留块、采样坐标、触发值、八项计算特征、同步通道心率及可用的 JEV 分数。选方和审核每批至多四项。该入口使用 `thinking.type=disabled` 和 4,096 输出 token 上限，保存实际模型返回的用量。原编程 Agent 有自己的长会话参数。[DeepSeek 接口说明](https://api-docs.deepseek.com/guides/anthropic_api)
- 停止时使用工作台按钮，或在工作区创建 `stop.requested`。CLI 使用相同规范和工作区追加 `--resume`。运行锁避免并行写同一工作区，已完成记录的波形、探针、证据与回执会核对后复用。可用 `receipt_seed` 指定同协议的既有工作区，真实运行仅复用输入、图像、模型配置和决策摘要均匹配的已存回执，缺项重新决策。严格离线复演时，在新规范中设置 `config.replay_from` 为原工作区路径。使用新工作区，命令可省略 `--live`。输入或取证不匹配时会报告缺失或不一致。

## 实际执行与产物

本地规则对照采用已有自适应 DSP，原始提示与原生测量相交时标待核。双角色模式使用同一个 DeepSeek 后端的独立请求上下文。条件按组制定，再逐一应用于原始采样坐标。联合看图针对当前版本的原生测量键提交默认状态和逐拍例外。发生冲突时取较保守的直接判定。健康通道不随其它缺失通道一起失败。

审计后先在原始观测上执行 identity、固定 DSP、自适应 DSP。Agent 将有不同输出的粗修候选按通道、候选方法及操作类型分组，用典型和边界实例看图选方。ECG 候选插值碰到原生峰前后 80 ms 时先保留原值并送联合核查。独立审核获选的实际改动，再在粗修结果上做患者级幅值、速率、通道形态及可选探针分歧筛查。修补角色阅读各组典型和边界图，提交可逐条执行的波形和测量条件。对冻结尖峰检测器定位且避开搏动保护区的完整孤立短脉冲，可选 SignalMind 线性插值。这条路径限检测器定位的 1–4 个采样点，同时受 5 秒事件上限约束。按单个候选核对两侧观测、接缝和邻近搏动位置，经单独看图接受后标成估计。其它成员仍可保留波形或标记停用。独立角色查看候选前后、重点跨通道事件和阴性对照，能对同一处不同搏动作不同裁决。数值修改交由已有 SignalMind/DSP 算子完成。局部任意 Python 配方、长期记忆晋升以及 TimesFM 候选仍沿用各自既有入口和规范。

| 位置 | 内容 |
|---|---|
| `records/<record>/` | 患者基线、问题组、精修计划、每条提示的实际处置、跨通道位置及逐拍例外、证据图、逐处数值试修与复测账本 spike-trials.json 和 30 秒图册 |
| `export/waveform_manifest.json` | 每个输入块的波形和探针路径、内容哈希、实测可用区、估计区和样本范围。文件引用相对本工作区 |
| `export/measurements.csv` | 全部原生 RR/PPI/逐拍压力，含 `quality`、受影响组、独立复查编号与波形版本 |
| `export/usable_measurements.csv` | 仅含 `quality=keep` 的行。`review` 为待核，`withhold` 为本轮排除 |
| `export/evaluation_report.json` | 覆盖、失败与未决原因、分组和复测数量、增量模型用量及运行状态 |
| `dataset-receipts/`、`jev-receipts/` | 分别绑定 DS 看图决策与 JEV 分流输入。真实数据无干净参照时，准确率为空 |

当前入口验证的是完整工程流程与可复现性。图上有代表、模型给出“保留”、以及真实测量准确率属于不同的评估口径。
