# 全库质量探查、受控修补与发布

本版落实《SignalMind 项目建议包 v1.0》的风险优先顺序。清洗支持 ECG/RR、PPG/PPI、ABP 逐拍压力；CSV/NPZ 的 RESP 支持仅质量探查。论文算法卡可登记方法、适用条件、验证数据和参考来源。[算法卡契约](../../src/tsmcp/cleaning/knowledge.py)

## 默认入口怎样决定一处能不能改

1. 文件导入保留患者、通道、连续采集块及半开采样范围。默认各文件独立。对同一记录的有序存储分片，可在 CSV/NPZ 映射中显式给出 `storage_shards`，如 `{"record-A":["part1.npz","part2.npz"]}`。各通道需要实测时间轴，真实时间跳变处分块。
2. 本地哨兵覆盖全输入。突变比值用排除待查小窗的有限邻域稳健幅值计算，双相尖峰有独立短事件定位。5–100 秒窗口保留极端、分位数、异常时长及支持范围；短事件探查独立运行。ECG 探针分别登记可评估、边界不确定、不支持及检测不到事件的区间。ECG 首尾 160 ms 是旧探针本身的定位边界。
3. 先审计原始输入，完成粗修候选与程序验收，再按粗修版本为所有目标记录生成候选与证据。冻结范围包含全部必需检查。未完成时交付已知范围、失败原因和待核状态。冻结后，诊断角色对每个逻辑组读取两张代表图；小组附完整表，大组先附统计和典型、边界成员的数值。它给出伪迹、生理事件、混合或未知以及替代解释。规划角色在独立请求中读取固定诊断与每一行成员数值，大组拆页复用同一份看图回执，选择带条件的注册操作。
4. 计划包含输入版本、候选修订、算子与参数、读写范围、保护范围、预期结果和验收规范。数值试修、用途停用、原样保留分别记账。程序硬门对照父版本重新计算实际写入、支持及生理证据。插值检查双侧锚点、检测器支持、原始局部极值、邻拍形态和节律；工频工具检查目标频率能量和生理包络，ABP 还须保留直流。局部去趋势检查邻近 QRS 幅值。硬门未通过时无法生成接受补丁。
5. 发布复查先独立看前后图，再读取真实复测和前次观察回执。可以接受、保留、退回、要求补证或确认用途停用。需要证据时可扩大视图，退回和新发现可进入一轮重新归因、规划、试修。达到上限的进一步改动记为未解决。发布补丁绑定父版本、候选版本、修订、证据与硬门。最终波形再次全范围扫描，新增、持续、消失和证据失效的候选进入账本，逐拍结果仅使用当前连续实测支持。
6. 角色记忆与技能快照在运行前固定。修补和复查分别检索自己的有限经验，客观执行结果保存在共享库。运行中写入的经验供后续运行选择。程序独立核验已注册的算子及验收门槛。

## 短尖峰的修补与复查

同一孤立尖峰组可包含可试修成员和受保护成员。成员表逐行记录预检状态；两类同时存在时，两张组图各展示一个代表。诊断回执保存整组以及可试修子集的判断。规划选择插值时，条件须命中本页至少一个可试修成员，否则模型收到实际校验原因并重新提交，也可以明确保留。受保护成员保留观测，可用性另行判读。

每处短尖峰仍执行双侧实测锚点线性插值。复查看到同步通道上下文、逐点原始和候选值、相同支持下的前后事件，以及条件允许时的邻拍同相位波形。邻拍取自同一连续观测段，排除目标周期；仅用核心两侧的观测对齐局部水平。图中同时报告估计点数和无效点数。邻拍差异是供复查判断的证据，独立硬门与发布回执共同决定交付。[开发集配对实测](../../eval/results/spike-repair-20261124/README.md)

## 如何查看和复现

| 产物 | 可以核对的内容 |
|---|---|
| `inspection/coverage.jsonl`、`negative_audit.jsonl`、`unknown_audit.jsonl` | 各检查的支持与适用性、无告警和支持不足两个抽样总体 |
| `ledger/freeze.json`、`records/<record>/discovery.json` | 整库冻结标志、初始版本、采样与时间坐标、证据和阈值 |
| `records/<record>/plans/`、`patches/` | 可执行计划、逐版本批准、幂等键、父版本和回退依据 |
| `records/<record>/rescan.json`、`ledger/candidates.jsonl` | 复扫差异、最终处置、证据、测量策略和补丁引用 |
| `ledger/run.json`、`acceptance-spec.json`、`knowledge-snapshot.json` | 实现、规范、角色经验和技能快照 |
| `export/`、`context-usage.json` | 已发布波形与支持、逐拍表、按记录消耗的请求配额及单独的耗时与用量报告 |

工作台“候选账本”可按状态筛选并查看单条证据。对应接口为 `GET /api/runs/{rid}/quality?state=need_evidence&offset=0&limit=50`。规范示例见[整库入口](dataset-entry.md)。

```bash
.venv/bin/tsmcp-clean contracts --out /tmp/signalmind-contracts
.venv/bin/tsmcp-clean dataset --spec configs/cleaning/dataset-entry.example.json --workspace /tmp/signalmind-run
.venv/bin/tsmcp-clean rollback --workspace /tmp/signalmind-run --patch <已发布补丁键> --out /tmp/signalmind-rollback
```

回滚导出恢复该块的确切父版本，撤销依赖它的后继，重新导出原生测量。受影响同步块保留待核，来源工作区可继续核对。整库清洗结束后可用 `tsmcp-review-pattern --inspection <工作区>/ledger` 按候选 ID 发起后续形态复查，也兼容旧冻结清单。实际调用模型沿用该运行已授权的费用账本。

## 预算、技能及研究

`quick / balanced / deep` 读取执行包的窗口、步长、图片和调用档位；旧名 `thorough` 指向 `deep`。三档的默认每记录模型请求额度为 8、24、64，每次图片上限为 4、6、8。可覆盖 `max_llm_calls_per_record`、`max_images_per_call`、`max_text_bytes`、`max_request_tokens`、`max_output_tokens`、`max_request_seconds` 和 `inspection_wall_seconds`。组内数值按可验证的成员索引拆页；预算不足的页保持待送审。文本字节数、图像尺寸换算的预留 token 单位和输出上限用于本地准入，实际 token 以服务端回执为准。

`tsmcp-clean knowledge` 提供论文元数据检索、算法卡登记、沙箱试验与技能版本管理。可用 `knowledge_root` 为 CLI 指定本地经验库。算法卡包含来源、版本、公式或步骤、边界条件、实现差异和验证限制。候选经验通过以下过程成为可检索的正式技能。

```text
proposed → sandboxed → evaluated → approved → active → deprecated
```

`trial` 调用既有隔离 worker 复现注册算子。晋升使用真实试验版本、回归与留出集的审计主体和参考哈希，独立计算恢复误差和正常区改动。标坏目标不能算修回；同一输入或主体重复使用不能算独立验证。激活新版本会原子停用旧版；需要时可以重新激活已验证版本。两类模型都只能建议操作。技能管理命令由操作者执行。
