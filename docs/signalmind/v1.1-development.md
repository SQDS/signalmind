## 修补漏斗

`tsmcp-clean dataset` 在发布时写入 `export/repair-outcomes/`。要审计已有的 v1.0 整库归档，将结果写到独立目录：

```bash
.venv/bin/tsmcp-clean outcomes --workspace /path/to/completed-run --out /tmp/repair-outcomes
.venv/bin/tsmcp-clean contracts --out /tmp/signalmind-contracts
```

- `candidates.jsonl` 每个稳定候选 ID 一行，含初始冻结归属、各轮分组计划及条件、适用性、尝试引用、提交动作、复扫与未解决状态。一个区域内的最终样本变化可以来自其它候选；有直接补丁关联才给候选记提交。
- `attempts.jsonl` 每项实际进入执行路径的请求一行。候选生成、硬门、独立复查和补丁提交分别记账。共享的整块停用计划列出成员 ID；粗修块级操作单列。未进入算子的请求保留拒绝原因。归档中缺少的参数或时间可以为空；较早的过滤器合并前置条件错误保留原始语义。
- `api_calls.jsonl` 按实际调用编号去重，列出延迟、token 和用量估算。多成员共享的调用只计费一次；成员与尝试通过请求编号和回执引用取证。平台实扣独立于本地估算。
- `summary.json` 给出初始冻结分母、含复扫的新候选数、尝试数和提交数，并记录明细哈希。各原因可并存。公共导出不接触隐藏真值，MAE/gain 为空并标明缺少独立参照。

## 启用用途域

[开发配置示例](../../configs/cleaning/v1.1-short-core.example.json) 使用本地规则模式；[注册域](../../src/tsmcp/cleaning/profiles/human-vital-short-core.v2.json) 明确记录适用条件及校准状态。原有无版本声明的规格按 v1.0 解释，便于复现。新规格通过 `repair_protocol: "v1.1"` 启用显式域。物种、设备和用途由调用者声明，运行时还核对每个输入块的采样率、原生字段、单位、观测支持及时间轴。

```bash
.venv/bin/tsmcp-clean dataset --spec configs/cleaning/v1.1-short-core.example.json --workspace /tmp/signalmind-v11
```

当前域限 human/Vital/125 Hz 开发用途，记录持续秒数、局部周期与占比、双侧锚点和事件证据。ECG_RR、PPG_PPI、ABP_pressure 各自绑定原生字段及单位。ECG_morphology/ST 的独立验收尚无校准，声明该用途会得到 unsupported。缺失域、设备冲突或不支持的单位会保留观测并使相关测量待核。域配置与原硬门共同生成验收标识，进入候选修订、计划和复查回执。模型建议仍需经过现有程序门。

[本轮离线验收](../../eval/results/v1_1_start_20261124/README.md)覆盖记录归因与开发域约束。正式比较还需要后续开发、独立试点、模型与预算授权及冻结预注册。

## 2026-11-25 修补与开发回归

当前配置使用 `1.1-dev`。已有 `1.0-dev` 声明继续调用原来的短核心策略。六个观测锚点来自核心两侧各三点，试算从同一个父版本开始。候选先通过生理和版本检查，有三组以上合格邻拍时用同相位中位数筛选；缺乏同相位参照时优先提名通过检查的线性候选。正式 Agent 的复查仍决定能否发布。

## PR-07/08 的 T1 模型入口

`python -m eval.repair_benchmark.episode` 运行 `one_shot_planner`、`generic_tool_agent` 和 `signalmind_full`。每个病例先快照公开的观测与许可范围。一次性规划组只提交一次；通用组可按全局样本坐标读取数组和图片、试修或重选，候选句柄及证据均绑定到当前病例及运行。SignalMind 从同一清单开始，调用生产的分组、诊断、独立复查和返工，并通过公共执行器校验最终交付。声明为 Vital 的真实输入须提供其物种、设备、原生字段、时钟和归一化信息。三组可使用相同的初始证据，角色上下文和后续取证按各自流程产生。

缺失输出保留在分母内，误差回退到输入，测量交付覆盖为零。私有评分器分别计算候选和最终波形，记录越界尝试、获得批准的原生测量支持与缺失原因。按用途和单位预先给出正值 `reference_scale_floors`、每窗 `stratum` 后，才能计算固定尺度归一化误差；同类型窗口、类型、预设重复和患者依次等权。模型正式成绩按默认 `live` 模式核对，离线工程实验须显式声明 `arm_modes`。

离线端到端验证使用生成的波形和脚本响应。Linux 需支持 Bubblewrap 的命名空间。安装项目依赖后，在仓库根目录为隔离执行器准备数值环境，并在新的输出目录运行验证。

```bash
uv venv --python 3.12 eval/.venv-processing
uv pip install --python eval/.venv-processing/bin/python numpy scipy matplotlib jsonschema
.venv/bin/python -m eval.repair_benchmark.agent_smoke --out /tmp/signalmind-t1-smoke
.venv/bin/python -m eval.repair_benchmark.episode \
  --public /tmp/signalmind-t1-smoke/C001/public --out /tmp/signalmind-t1-replay \
  --arm generic_tool_agent --episode-id offline-protocol-1 \
  --replay /tmp/signalmind-t1-smoke/C001/generic_tool_agent/transport.json
```

DeepSeek 实测使用原生产共享账本、失败费用预留、运行级限额和真实传输回执。可选 `--experiment-budget` 把新增费用上限跨病例、实验组和重启累计。回放时核对每次请求的提示、工具和真实证据哈希。已归档的旧回执须使用对应的冻结方法代码。
